# 数学建模论文写作

默认由当前主 Agent 在同一会话中启用本 Skill。写作的任务是重建完整论证，而不是把工程报告、审计字段或模板槽位机械拼接成正文。

所有正文、图题、表题、坐标轴、图例和图内注释使用简体中文；公式符号、单位和通用技术缩写可保留。

## 输入范围

优先读取：

- `workspace/problem.md`、`brief.md`、`symbols.md`；
- 当前小问 `analysis.md`；
- 当前采用实验的 `outputs/report.md`、`metrics.json`、表、图和必要代码；
- 已核验的 `research/` 来源；
- `paper/manuscript.md` 的相邻章节。

默认不读取 `runs/`、`experiment.json`、`qc.json`、旧状态目录或 Agent 日志。它们只能用于主 Agent 排查复现问题，不能提供论文叙事。

## 写作方法

1. 先确定本节必须回答的题目问题和一句话结论。
2. 建立论证骨架：为什么这样建模、数学形式是什么、如何求解、结果是什么、为何可信、适用边界是什么。
3. 检查所有数字、公式、比较和领域事实均有当前数据、代码或来源支持。
4. 按自然论证组织段落，不按输入文件顺序转述，不展示内部追溯编号。
5. 写完后从评委视角删去空泛背景、重复定义、流水账和没有解释作用的指标。

每个重要技术段落尽量形成“目的 -> 方法 -> 证据 -> 解释 -> 边界或承接”的闭环。没有证据的内容应回到主 Agent 或 Engineer 补足，不以免责声明填满正文。

## 论文结构

需要组织章节或做全文检查时读取 [论文结构与成文规则](references/fixed-paper-section-template.md)。该文件提供稳定章节功能和题型适配，不规定固定槽位数量、段数、候选数或模板句。

前置正文可在初步 EDA 后完成问题重述、问题分析、模型假设、符号说明、数据预处理与总体技术路线；摘要应在各问直接答案和验证结果稳定后写。

各问正文至少清楚呈现：

- 问题目标与分析单位；
- 变量、参数、假设和单位；
- 模型公式、约束及其含义；
- 求解或估计方法；
- 与题目动词对应的直接答案；
- 验证、敏感性或失败边界；
- 本问如何连接下一问。

不是每个问题都需要独立的“模型检验”或“优缺点”小节；按题型和真实证据组织，避免为了标题完整而重复。

## 数字和来源

- 不重新计算实验结果，不从图片目测数字，不把缺失结果补成合理值。
- 比较必须使用可比的样本、split、指标和约束。
- 领域事实与方法来源写入参考文献；实验文件路径只放在 `paper/evidence_notes.md` 等内部笔记，不进入可见正文。
- 用户强制采用存在风险的结果时，正文如实写科学局限，但不写 Harness override 或 QC 状态。

## 图表

正式图首先定义要支撑的结论、数据字段、分析单位和面板职责。所有图都要检查数据忠实性、标注、单位、图例、色觉可辨性、字号和版面适配。

Writer 只定义 Figure Spec、安排正文位置和消费最终图；不得自行绘制 EDA、结果或论文图。任何生成、重绘、修订或审查图形的工作都必须调用 Writer 的独立 `$create-modeling-figures` Skill。

需要高质量论文图时：

1. 调用 `$create-modeling-figures`，提供 Figure Spec、已核验数据和论文结论边界。
2. 由 Figure Skill 选择性使用 ModelViz 召回图型线索，并强制调用 `$nature-figure` 基于真实数据原创中文多面板重绘与视觉 QA。
3. Writer 消费该 Skill 返回的最终图、图题、正文解释和边界说明；图、脚本与简洁来源说明位于当前问 `figures/` 或 `paper/figures/`。

组合流程详见 [ModelViz 与 Nature-Figure](references/hybrid-visualization-pipeline.md)。不要让图表工具新增统计结论、改变筛选口径或替代主 Agent 对结果的解释。

## 修订和终稿

修订时先判断问题属于写作表达还是上游分析：

- 表达、结构、术语、交叉引用和版式问题直接修改。
- 数值、数据处理、模型假设、验证或结论问题退回主 Agent 或 Engineer。
- 来源不足的问题按需调用 Librarian。

终稿检查重点：

- 摘要逐问给出方法、直接结果、单位或参照及可信性证据；
- 题目要求没有漏答；
- 符号、单位、样本量、公式和图表编号全局一致；
- 每个图表在正文中被解释，而非只被引用；
- 结论没有把相关性升级为因果；
- 不残留 TODO、模板占位、内部路径、Job、artifact、staging、QC、token 或 Harness 术语；
- 官方格式要求优先于外部模板。
