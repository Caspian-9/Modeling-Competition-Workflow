# 数学建模学术检索协议

本协议用于按需检索。目标是回答主 Agent 提出的具体研究问题，不追求形式化系统综述，也不为普通小问制造额外流程。

## 查询设计

将问题拆为少量互补查询：

- 研究对象、机制、定义和领域术语；
- 数学模型、关键假设和适用条件；
- 验证、泄漏、不确定性和失败模式；
- 官方标准、公开数据或参数；
- 可复现实现和代码仓库。

需要时同时使用中文和英文术语。每个查询应能说明它要解决哪个具体判断，连续扩大关键词但不改变问题含义。

## 来源优先级

1. 官方机构、标准和一手数据；
2. 同行评议论文、权威教材和出版社资料；
3. 数据集原始文档；
4. 固定 commit/tag、许可证清楚且实现透明的代码仓库；
5. 搜索结果、博客或社交页面仅作发现线索。

引用量、期刊名气、仓库 star、搜索排名或 LLM 回答都不能单独证明结论。

## 核验

对准备保留的来源记录：

- 标题、作者或机构、年份、venue；
- DOI 或稳定 URL；
- 访问日期；
- 实际阅读深度：全文、摘要、metadata、仓库文件或仅线索；
- 它支持的具体陈述；
- 可迁移条件、与当前数据的差异和局限。

关键领域事实尽量由独立来源交叉核验。区分相关、预测、机制和因果证据；预印本和摘要级核验必须明确标注。

## 去重和筛选

优先按 DOI 去重，其次按规范化标题、作者和年份。排除重复、对象不符、机制不符、无法核验、非学术材料或同题答案污染，并保留简洁理由。

来源证据等级与筛选状态分开记录：

- 证据等级沿用 source catalogue 的 A/B1/B2/C1/C2/D；
- 筛选状态可用 `verified_direct`、`priority_read`、`background`、`excluded`。

## 检索日志

只记录实际执行的查询：来源、检索式、日期、过滤条件、可见命中、保留项、排除理由和访问障碍。对 API 可记录 endpoint 与非敏感参数，不记录 credential。

网络失败、限流、空结果和元数据不完整都如实记录。不得声称访问了未实际打开的数据库，不得绕过登录、付费墙、验证码、robots 或 rate limit。

## 停止条件

满足以下条件即可停止：

- 当前关键判断已有可核验来源，或已明确不存在足够证据；
- 关键事实完成必要交叉核验；
- 方法适用条件、验证负担和主要失败风险已清楚；
- 连续两个合理查询没有产生新的高价值信息。

后续只针对明确缺口做 focused follow-up，不重复全量检索。

## 交给主 Agent

用主题综合而非逐条文献摘要回答：

- 这些证据支持或反对哪个模型判断；
- 可采用哪些假设、参数、验证或实现；
- 当前数据仍必须检验什么；
- 哪些结论只能弱写；
- 哪些路线应排除及原因。

文献结果不能替代当前数据实验，也不能直接决定最终模型。查询日志和访问障碍留在 `research/`，论文只引用经过核验且实际支撑正文陈述的来源。
